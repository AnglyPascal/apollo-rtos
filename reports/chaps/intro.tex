\section{Introduction}

\subsection{Background \& Motivation}

Computing capabilities have grown at an unprecedented rate over the last century. The
\textbf{Apollo Guidance Computer} (AGC), which played a critical role in the Apollo
program, operated with a modest \textit{2 MHz CPU}, \textit{4 KB of RAM}, and
\textit{72 KB of ROM}. To maximize its limited resources, the AGC's operating system
introduced innovative solutions for \textit{task scheduling}, \textit{error handling},
and \textit{resource-efficient computation}. One of its most groundbreaking features
was a hybrid scheduling mechanism that combined cooperative and preemptive
multiprogramming, ensuring that critical tasks could execute reliably even in adverse
conditions. Additionally, the AGC incorporated a robust recovery mechanism, enabling
fault tolerance in the face of system failures.

Today, a compact \texttt{micro:bit} device costing less than \pounds20 possesses
significantly more computing power than the AGC. Such microcontrollers are now
ubiquitous, powering applications ranging from consumer electronics to mission-critical
systems. Despite the vast improvements in computational power, many of the challenges
that the AGC’s operating system addressed remain highly relevant, particularly in
constrained embedded environments where real-time performance, reliability, and fault
tolerance are essential.


\subsection{Project Summary}

This project investigates the design of the Apollo Guidance Computer (AGC) operating
system and explores how its core ideas—most notably its hybrid cooperative-preemptive
scheduling and fault-tolerant recovery—can be adapted to modern embedded systems. The
result is \textbf{Apollo-RTOS}, a fully-featured real-time operating system implemented
for the \texttt{micro:bit} v1 device.

Apollo-RTOS faithfully adapts several AGC concepts such as priority-based cooperative
multitasking, a preemptive task queue, and a system-wide recovery mechanism that
tolerates resets and hardware faults. These are combined with modern operating system
abstractions including dynamic memory allocation, file systems, inter-process
communication, and a Unix-like shell interface. The implementation is written in modern
C++, leveraging RAII, templates, and static typing for safety and performance.

At the architectural level, Apollo-RTOS follows a \textit{monolithic kernel design},
incorporating a compact scheduler and a recovery-aware process model. It also includes
a modular file system stack with support for both flash and FRAM-backed block devices,
along with lightweight drivers for peripherals including UART, display, and I2C-based
sensors. Developers interact with the OS using a shell and a suite of programmable
applications, written against a familiar C++ API. An integrated testing framework
supports unit and subsystem testing.

\paragraph*{Key Contributions}
\begin{itemize}[left=0pt]
    \item A lightweight, deterministic \textbf{hybrid scheduler} combining cooperative
        and preemptive semantics. [\autoref{sec:sched}]
    \item \textbf{Fault-tolerant process recovery} and boot-stage awareness using
        AGC-inspired restart groups. [\autoref{sec:rec}]
    \item \textbf{Dual file system support} over flash and FRAM devices using a shared
        template-based backend. [\autoref{sec:mem}]
    \item A minimalist \textbf{Unix-like shell interface} with support for foreground
        apps and command dispatch. [\autoref{sec:shell}]
    \item A robust, modern \textbf{C++20 implementation} using RAII, templates,
        constexprs, and type deduction.
    \item A \textbf{unit and integration testing framework} to validate system
        components in isolation. [\autoref{sec:testing}]
\end{itemize}

Apollo-RTOS demonstrates that historical system design choices, when reinterpreted
through the lens of modern software engineering, can lead to elegant and effective
solutions for contemporary embedded platforms. It provides a practical example of
building robust, modular systems under tight resource constraints while remaining
extensible, maintainable, and developer-friendly.
